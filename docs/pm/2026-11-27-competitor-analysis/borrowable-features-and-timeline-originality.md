# 值得參考的功能，以及時間軸是不是獨創（2026-11-27）

> 依據：`competitor-analysis.md`、`policy-island-imitations.md`，加上這次直接讀前端程式碼的結果。
> 檢查的程式碼：HEART 的 app.js（v=20261119-1）與 index.html；柯P市政島、何欣純、新北政見島、臺北施政島的頁面和前幾支 JS。
> 臺北施政島是 React 打包的程式碼，只檢查到一部分。

## 一、時間軸是不是獨創？

**結論：「時間軸」這個元件不是獨創，但我們的做法在檢查範圍內沒人做過。**我們的做法是：用真實的歷史日期，拉一條連續的滑桿，讓島一路長出來，政績物件依序出現、狀態從藍圖、施工變成實體，最後還能匯出影片。

| 作品 | 有什麼「時間」功能 | 跟我們的差別 |
|---|---|---|
| HEART | 【觀察】「01 台北人的一天」：00:00–24:00 的滑桿加「▶ 播放一天」，切換日夜光影、點亮不同的建築 | 模擬的一天，不是歷史 |
| HEART | 【觀察】「02 任期時間軸」：5 個按鈕（就職、6 個月、第 1–2 年、第 3–4 年、第 5–8 年），點了會標亮政見裡說要在這個階段做的建築，卡片標題是「政見所述階段」（`setTerm`、`D.termTimeline`） | **未來的承諾**、分段按鈕、只是標亮，沒有東西長出來 |
| 何欣純政見互動地圖 | 【觀察】「▶ 播放一天」的時間滑桿（05:00–23:00）；「人生時間軸」分頁，依人生階段排政策 | 模擬的一天，以及人生階段 |
| 柯P市政島 | 【觀察】政績大事記每件都有日期；「依任期篩選」分成第一任、第二任、跨任期、待分期；「60 秒自動播放」每件約 6 秒自動切換；文案寫「重點是分清楚規劃、動工、完工，以及跨任期的部分」 | **最接近我們**：一樣是歷史政績，也分了階段。但它是分任期的篩選加卡片輪播，島不會長出來 |
| 臺北施政島 | 【觀察】每項政策標示已完成、進行中、規劃中 | 有狀態標籤，但檢查到的程式碼裡沒有時間軸 |

**推論：**
- 「播放一天」已經是政策島的標準配備，「依任期篩選或排序」也出現了兩次（HEART、柯P）。所以時間軸這個詞不能當賣點講。
- 檢查範圍內**沒人做的**有三件事：連續的歷史時間軸、島隨時間長出來、匯出影片。
- 柯P市政島證明了「區分規劃、動工、完工」這個概念有人想到。但我們把它畫成藍圖、施工、實體三種外觀，再讓它隨時間變化，這個做法沒人做過。
- 沒檢查到不等於不存在：臺北施政島只看了部分程式碼，Threads 上的作品也沒查。

**意涵（對外怎麼說）：**不要說「首創時間軸」。說「**看四年的足跡怎麼一步步長成今天的北海岸**」，強調真實歷史和成長，避開被拿去跟 HEART 的時間軸比。

## 二、值得參考的功能

| 優先 | 功能 | 來源 | 我們的版本 | 放哪一期 |
|---|---|---|---|---|
| 高 | 「規劃、動工、完工」與「跨任期、不等於全部歸功」的說明文案 | 柯P市政島 | 側欄和說明裡講清楚：議員的角色是爭取、監督，實體建築代表「已落地」，不代表「她蓋的」 | 第一期 |
| 高 | 不用 3D 也能看的清單 | 何欣純（「請改用下方的清單…內容完全相同」） | 手機太舊或 WebGL 開不起來時，退回依時間排序的文字清單 | 第一期 |
| 高 | 事件追蹤 | HEART（gtag `heart_island_panel`） | 記錄播放、拖滑桿、匯出影片的次數，用來判斷時間軸有沒有人用 | 第一期 |
| 中 | 找我家附近 | 妃妃鐵馬（查路名看車隊會不會經過你家） | 輸入地名或里名，飛到那一格，看那附近發生過什麼 | 第一期之後 |
| 中 | 服務處觸控機模式 | 台南政策島（「總部觸控機」模式） | `?kiosk=1`：時間軸無限循環播放，放在服務處的螢幕上 | 第一期之後，成本很低 |
| 中 | 每週檢查連結 | 臺北施政島 | 排程檢查文章連結和圖片是否失效 | 第二期，跟社群分析排程一起做 |
| 中 | 每日由 AI 排程更新 | 今日群島 | 第二期的社群分析 | 第二期 |
| 低 | 合照、角色收集 | 大港政策島、HEART（拍照模式、heart-me） | 跟議員角色合照的分享圖 | 再看看 |
| 低 | 投票日暫停分享 | 新北政見島 | 選舉期間的投票日關閉匯出和分享，下次是 2030 年 | 之後 |
| 中 | 活動預告、加入行事曆 | 妃妃鐵馬（全部日程） | 站路口、座談這類公開活動：島上倒數、加入行事曆（.ics） | 第二期，見 `docs/superpowers/specs/2026-11-27-where-is-councillor-notes.md` |

**車掃路線**（選舉期間）屬於「即時位置」的範圍，要照第二期筆記裡的安全原則處理。

**跟定位有關的功能**（找我家附近、活動預告、今天的足跡）都要遵守第二期筆記的安全原則：

- 不存也不公開座標
- 不做持續追蹤
- 「現在在這裡」預設在離開之後才公開
- 不做讓人看出固定習慣的統計

不建議參考的：
- 靜態分享卡（妃妃鐵馬、新北政見島的限動分享圖）：**使用者決定不做**（2026-11-27）。分享一律用影片。
- 測驗（「你是哪一種台北人」）、集章：跟「累積和回顧」的目的無關，只會讓功能變雜。
- 鄉親布告欄（開放投稿、先審後刊）：我們的「鄉親的話」是挑選後經本人同意才刊登，比較嚴謹，不改成開放投稿。
